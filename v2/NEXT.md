# 다음 세션 작업 지시 (Opus용)

Fable이 2026-10-16에 v2(Screens v1 디자인) 뼈대를 작성해 둠. v1을 복사한 뒤 `styles.css`, `components/Shell.tsx`(새 파일), `components/Row.tsx`, `screens/*.tsx`(Shell로 감싼 것만)를 바꿨다. 동작 코드(`App.tsx`, `data.ts`, `icons.tsx`, 나머지 components)는 v1 그대로. 구조나 토큰 값을 바꾸지 말 것. 판단이 필요한 새 문제가 나오면 바꾸지 말고 사용자에게 보고.

## 할 일 (순서대로)
1. `cd v2 && npm install`
2. `npm run build` — 금지어 검사 + tsc + vite 빌드. 오류가 나면 **오류 메시지가 가리키는 그 지점만** 고치고 다시 빌드.
3. `npm run dev`로 띄워서 완료 조건 6개 확인 (docs/POLARIS_MVP_SPEC.md §7). v1 때와 같은 방식(playwright-core 헤드리스 크롬, 스크래치패드에서).
   1. M1 → M2 → M3 → M4 → M1이 버튼만으로 돈다
   2. M1·M2에서 X1 열고 뒤로 가면 원래 자리(스크롤 포함)
   3. M3 빈 입력이면 버튼 비활성, 새로고침해도 문장 유지
   4. 390px에서 가로 스크롤 없음
   5. 금지어 검사 통과, 고지 문구 모든 화면 하단
   6. 이미지 자리는 회색 상자
4. 추가로 v2에서만 볼 것: 시트가 화면 끝까지 내려가는지(짧은 화면에서 시트 아래로 캔버스색이 보이면 안 됨). 아코디언 펼침·접힘 때 `.seg` 테두리가 깨지지 않는지. 스크린샷 5장(M1·M2 펼침·M3·M4·X1)을 390 너비로 찍어 사용자에게 보여줄 것.
5. 루트 README.md의 폴더 표에 `v2/` 줄 추가 (아래 문구 그대로):
   `| \`v2/\` | Screens v1 민트 디자인 (피그마 파일 1, "3 Screens v1" 페이지). 기능은 v1과 같음. 결정 기록은 \`v2/DECISIONS.md\` |`
   그리고 실행 설명에 "v1 자리에 v2를 넣으면 v2가 뜬다" 한 줄.
6. 확인되면 사용자에게 보고. **커밋은 사용자가 말할 때까지 하지 말 것.** (v1/ 폴더 이동도 아직 미커밋 상태라 같이 묶일 수 있음 — 사용자에게 물어볼 것.)
